# Editorial — Frontend

Клиентское веб-приложение для издательской платформы **Editorial**.
Разработано на **TypeScript + React (Vite)** в соответствии с дизайн-системой **Editorial Minimal** и контрактом микросервисного бэкенда **EditorialWeb**.

---

## 🚀 Быстрый старт

### 1. Установка зависимостей
```bash
npm install
```

В PowerShell при блокировке `npm.ps1` используйте `npm.cmd install`,
`npm.cmd run dev` и `npm.cmd run build`. Менять execution policy не требуется.

### 2. Запуск локального сервера разработки
```bash
npm run dev
```
Приложение откроется по адресу `http://localhost:5173`.

### 3. Сборка для production
```bash
npm run build
```

## 🔌 Режимы работы с API

В шапке приложения предусмотрен удобный переключатель между двумя режимами:

1. **Gateway :8080 (по умолчанию при наличии бэкенда):**
   Запросы проксируются на Spring Cloud Gateway (`http://localhost:8080`), развёрнутый через Docker Compose из `C:\EditorialWeb`:
   - `/api/auth/**` → `auth-service`
   - `/api/articles/**` → `article-service`

2. **Mock API (автономный режим):**
   Позволяет тестировать функционал с сохранением демоданных в `localStorage` без запуска бэкенда. Включается явно переключателем в шапке. При переключении режима текущая сессия сбрасывается, чтобы реальные и демонстрационные токены не смешивались. Сетевые ошибки в режиме Gateway показываются пользователю и не включают Mock API автоматически.

## Контракт API

Источники: `C:\EditorialWeb\editorial-docs\article-service\README.md` и
`C:\EditorialWeb\editorial-docs\auth-service\README.md`, сверенные с контроллерами и сервисами проекта.

- Чтение статей требует входа. Основной каталог запрашивает только `status=PUBLISHED`.
- Разделы «Мои статьи» и «На проверке» используют `/api/articles/my` и `/api/editor/articles`.
- Списки возвращают Spring Data Page. Фронтенд загружает все страницы по 100 элементов, затем применяет существующие поиск, сортировку и пагинацию по 6 карточек ко всему результату.
- Read DTO использует `articleId`, `authorId`, `authorDisplayName`. Ответы создания, обновления и персональных списков используют `id`, `authorAccountId`. API-адаптер приводит оба DTO к общей модели интерфейса.
- Действия со статьёй учитывают роль, владельца и статус. Доступны отправка на проверку, одобрение/отклонение, архивирование и возврат из проверки в пределах прав бэкенда.
- После регистрации вход выполняется отдельно: аккаунт может оставаться `PENDING`, пока Kafka-событие создания профиля не обработано.
- Обновление токенов выполняется одним общим запросом для параллельных обращений. Тестовая смена роли доступна только в Mock API; реальные права приходят из JWT.

Проверка контракта и прав: `npm.cmd test`. Проверка TypeScript и production-сборка: `npm.cmd run build`.

## 🎨 Дизайн и функционал

- **Типографика и цвета:** Полное соответствие спецификации `design/editorial_minimal/DESIGN.md`: шрифты `Inter` и `JetBrains Mono`, палитра `#111827`, `#4b5563`, `#f8f9fa`, `#e5e7eb`.
- **Вход и регистрация (`/auth`):** Точная реализация макетов `design/code.html` и `screen.png`.
- **Каталог статей (`/`):** Адаптивная сетка, поиск по заголовку и содержанию, фильтр по авторам, сортировка и пагинация.
- **Читалка (`/article/:id`):** Чтение статьи в центрированной колонке 720px с поддержкой **Markdown** (заголовки, цитаты, списки, листинги кода), регулировкой кегля шрифта (А− / А+) и быстрым копированием ссылки.
- **Редактор статей (`/editor`):** Создание и редактирование статей с панелью быстрого Markdown-форматирования и вкладкой интерактивного **предпросмотра** в реальном времени.
- **Контроль прав доступа:** Роли `USER` (чтение), `AUTHOR` (управление своими статьями), `EDITOR` и `ADMIN` (редакционные действия с учётом статуса). Dev-переключатель ролей доступен в Mock API.
