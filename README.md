# Editorial — frontend

React + TypeScript + Vite. Клиент для backend в `C:\EditorialWeb`.

## Запуск

```powershell
npm.cmd install
npm.cmd run dev
```

Адрес: http://127.0.0.1:5173/. Vite проксирует `/api` на http://localhost:8080. Для API нужен работающий backend. Сервер разработки должен оставаться запущенным.

```powershell
npm.cmd test
npm.cmd run build
```

## Реализованные сценарии

- Регистрация и отдельный вход после создания профиля, обновление JWT, выход. Нет неработающих настроек запоминания сессии, восстановления пароля или ссылок на отсутствующие юридические документы.
- Новостная лента опубликованных статей: первый материал выделен крупно, остальные показаны отдельными карточками. Поиск, фильтр автора и пагинация сохранены. Сортировка учитывает publishedAt, затем createdAt, затем ID. Поддерживаются новый `authorInfo` с именем и ключом аватара, ответы сущностей `Article` и прежний DTO. Отсутствие профиля не подменяется вымышленным именем.
- Создание черновика, редактирование с Markdown-предпросмотром, отправка на проверку, модерация, архивирование, возврат из проверки и удаление с учётом роли, владельца и статуса.
- Загрузка/замена обложки, загрузка/список/замена/удаление изображений статьи, вставка публичного файлового URL в Markdown. После создания черновика открывается редактор для добавления файлов. Поддерживаются JPEG, PNG, GIF и WebP до 10 МиБ; HTTP-лимит backend может быть меньше.
- Профиль берётся из `/api/users/me`; имя и описание сохраняются через PATCH, пустая строка очищает поле. Аватар загружается multipart на `/api/users/me/avatar`, изображение показывается через публичный `/api/files?key=...`.
- Страница автора показывает только его опубликованные статьи и данные автора из ответа статей. Несуществующий `/api/users/{id}` не вызывается; дата регистрации, биография и роль не придумываются.
- Комментарии: чтение всех страниц, создание, вложенные ответы, редактирование своего комментария и логическое удаление по правилам `CommentService`. Форма ответа открывается прямо под выбранным комментарием с фокусом без прокрутки. После отправки раскрывается его ветка; фоновое обновление не размонтирует открытые формы и ответы. Все роли с JWT могут комментировать опубликованные статьи.
- Все девять реакций показаны эмодзи со счётчиками, подсказками и доступными названиями. Чтение счётчиков, установка, замена и удаление своей реакции через API. Повторное нажатие выбранной реакции снимает её. Выбранная реакция сохраняется после успешного запроса в localStorage отдельно для аккаунта и статьи. Повторное нажатие снимает её. Backend не возвращает текущую реакцию аккаунта, поэтому изменения с другого устройства не синхронизируются.
- Администратор: все страницы аккаунтов/профилей, чтение аккаунта по ID, изменение email/username/роли, имени/описания профиля. Новая роль применяется backend после выпуска нового JWT.
- Закладки работают локально, отдельно для аккаунта, с пустого списка. Старые демонстрационные данные не импортируются. Рекомендации, подписки, Pro, история чтения и настройки-заглушки удалены.

Верхняя панель содержит навигацию с активным разделом, кнопку «Написать» по правам пользователя и раскрывающееся меню аккаунта. На мобильных устройствах навигация открывается отдельной кнопкой; меню закрываются по Escape и при переходе.

## Ограничения контракта backend

- `coverObjectKey` читается из `GetArticlesResponse` и сущности `Article`. Обложки отображаются в ленте, на странице автора и перед текстом статьи через `/api/files?key=...`. Без ключа или при ошибке изображения сохраняется текстовая вёрстка без выдуманных картинок.
- Отдельных методов удаления обложки и аватара нет; таких кнопок в интерфейсе нет.
- Нет публичного профиля другого пользователя, списка его реакций, серверных закладок, подписок, рекомендаций или истории чтения. Внутренние batch/file API не вызываются браузером.
- Причина отклонения передаётся в модерации и читается из rejectionReason в DTO статьи; автор видит замечания в панели.
- Multipart-клиент не задаёт Content-Type вручную, чтобы браузер сформировал boundary. Пустые HTTP 200 и 204 корректно обрабатываются.

## Разработка

Фронтенд работает только с реальным API. Демо-режим, генератор тестовых данных и локальная смена роли удалены. Если браузер сохранил сессию старого демо-режима, она сбрасывается при запуске; нужно войти в настоящий аккаунт. Реальные роли берутся из JWT backend.

Основание контракта: контроллеры, DTO, `SecurityConfig` и `editorial-docs` backend. Внутренние сервисные методы, Kafka, JWKS и операции обслуживания MinIO не являются пользовательскими функциями фронтенда.

## Кеш изображений и маршрутизация

В production service worker кеширует только успешные ответы изображений `/api/files`: максимум 100 файлов, срок 24 часа. Работает через HTTPS или localhost; в разработке не регистрируется. Ключ кеша включает object key. При замене файлов backend должен возвращать новый object key; прежний ключ может показывать прежнее изображение до суток.

При восстановлении сессии страницы ждут окончания проверки JWT, чтобы проверка прав не перенаправляла пользователя с текущего маршрута. Production-сервер должен возвращать index.html для клиентских маршрутов (SPA fallback), сохраняя отдельную обработку `/api` и статических файлов.

Регистрация отправляет необязательное displayName (до 40 символов), поддерживаемое auth-service.
